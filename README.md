# 遥测 UDP 代理（接收器 A/B 切换 + 固件联调演练）

遥测终端经 UDP 代理把短报文发给接收器，值班员在网页上切换接收器 A/B，
已建立的会话不受影响，回包不会送错设备。网页同时提供**固件联调演练**：
编排 2～8 步回包动作（立即回包 / 延迟回包 / 不回包），复现
“收下首条读数但不回包、等终端重传再回”这类故障。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 操作网页 + SQLite 持久化 + 演练编排 |
| `receiver/` | 本地接收器：普通端口原样回显，演练端口按步骤表动作，TCP 控制通道 |
| `docker-compose.yml` | 一键启动代理 + 接收器 A + 接收器 B |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证（59 项检查） |
| `testlibs/flask_shim/` | 仅供无 pip 环境跑验证脚本的最小 Flask 垫片，**不参与镜像构建** |

## 启动

```bash
docker compose up --build
```

- 操作网页：http://localhost:8080
- 遥测终端普通发送地址：`UDP <宿主机>:9000`
- 演练专用端口：`UDP <宿主机>:9100`（仅演练期间开放，未演练时无监听）

## 演练规则（固件联调故障复现）

1. **编排**：首页选择接收器 A 或 B，排 2～8 步动作：立即回包、延迟回包
   （最长 2 秒）或不回包。默认编排即“第 1 步不回包、第 2 步立即回包”，
   配合模拟终端同文重发即可复现目标故障。
2. **就绪后才开端口**：代理先经 TCP 控制通道把步骤表下发给接收器，
   接收器确认就绪后，代理才开放专用 UDP 演练端口 9100；启动失败则端口不开放。
3. **一轮一个终端**：一次只开一轮，每轮只接纳首个测试终端，其他终端的
   演练报文在代理和接收器两侧都被丢弃并记录。
4. **按实收顺序执行**：接收器对每条实收报文按顺序消耗一步，**同文重发也占
   下一步**；步骤用完后不再接纳演练报文，但已安排的延迟回包仍可在本轮
   结束前发出。
5. **结束即作废**：手动停止，或端口开放满 10 秒，立刻关闭演练转发并通知
   接收器取消全部待发回包；无法联系接收器确认时，页面红色提示“停止未确认”。
6. **旧回包不进下一轮**：每轮使用独立上游套接字，端口回收后进入 30 秒冷却；
   接收器停止时也会取消本轮 pending 定时器，双重保证旧回包不可能进入下一轮。
7. **普通端口不受影响**：9000 端口在演练期间照常收发，普通流量不消耗演练步骤。
8. **可观测**：首页展示接收器逐步实收的报文原文与执行动作、按终端实收顺序
   排列的回包原文，以及完整事件流（转发/丢弃/作废/停止确认）和最近 10 轮历史。

### 模拟终端

首页演练区可编辑多条报文（内容、连发间隔、可选固定本地端口），点击
“连发到演练端口”即由代理后端用真实 UDP socket 发出，并在后台收集回包，
按终端实际收到的顺序展示。演练未开始、本轮已有终端或步骤已用完时发送会被拒绝。

## 接收器端口与控制协议

每个接收器监听三个端口：

| 端口 | 协议 | 用途 |
|---|---|---|
| 9001 | UDP | 普通端口，原样回显（`DELAY:<秒>:` 前缀可单次延迟） |
| 9101 | UDP | 演练端口，武装前静默丢弃一切报文 |
| 9201 | TCP | 控制通道，JSON-lines（每行一条 JSON） |

控制命令：`arm`（下发 round_id 与步骤表，接收器回 `{"ok":true}` 即就绪）、
`stop`（结束本轮并作废待发回包，ack 带 `cancelled_seqs`）、`ping`。
演练期间接收器在武装连接上推送 `recv/action/reply/drop/cancelled` 等事件，
代理据此渲染逐步实收表与事件流。接收器武装带 15 秒 TTL 看门狗，
代理异常时接收器自行解除武装。

## 普通透传行为规则

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：报文与回包内容不做任何修改。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **迟到回包**：会话过期即关闭其上游端口，端口进入冷却期
  （`UPSTREAM_PORT_COOLDOWN`，默认 30 秒，应大于最大回包延迟）不再分配；
  因此相同 `IP:端口` 重建的新会话也不可能收到旧会话迟到的回包。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器保存在 SQLite（`proxy-data` 卷）重启后保留；
  会话与演练状态全在内存，重启即清空。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的普通 UDP 监听端口 |
| `DRILL_UDP_PORT` | `9100` | 演练专用 UDP 端口（仅演练期开放） |
| `HTTP_PORT` | `8080` | 操作网页端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `DRILL_MAX_DURATION` | `10` | 演练端口开放上限（秒），到点自动结束 |
| `DRILL_MAX_DELAY` | `2` | 单步延迟回包上限（秒） |
| `DRILL_MAX_STEPS` | `8` | 单轮最大步数（最小固定 2 步） |
| `DRILL_STOP_TIMEOUT` | `2` | 等待接收器停止确认的超时（秒） |
| `DRILL_RECEIVER_TTL` | `15` | 接收器武装看门狗 TTL（秒） |
| `RECEIVER_A/B_HOST/PORT` | 见 compose | 接收器普通端口地址 |
| `RECEIVER_A/B_DRILL_PORT` | `9101` | 接收器演练 UDP 端口 |
| `RECEIVER_A/B_CONTROL_PORT` | `9201` | 接收器控制 TCP 端口 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标持久化） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 普通透传上游端口池 |
| `DRILL_UPSTREAM_PORT_MIN/MAX` | `30000/34999` | 演练上游端口池（独立池 + 冷却） |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |

接收器侧：`RECEIVER_NAME`、`LISTEN_PORT`、`DRILL_PORT`、`CONTROL_PORT`、
`REPLY_DELAY`（普通端口默认回包延迟）、`MAX_DELAY`（普通端口延迟上限）。

## 本地验证（无需 Docker）

```bash
pip install flask          # 若环境无 pip，脚本会自动启用 testlibs 下的最小垫片
python3 scripts/verify_local.py
```

演练部分覆盖：未演练端口拒绝报文、参数校验、首条不回/重传再回、
单终端锁定与外来终端丢弃、步骤耗尽拒绝、普通端口不耗步骤、手动停止确认、
延迟回包作废、模拟终端连发与回包顺序、10 秒自动结束、轮间隔离、
并发开轮拒绝、接收器失联时“停止未确认”。普通透传部分覆盖原有全部行为
（原样透传含二进制、会话固定接收器、过期重建、迟到回包丢弃、网页试传、
重启持久化、保存失败保留原目标）。
